## `cloak_of_darkness/`

A complete three-room game, playable start to finish, and the first
example here that is a game folder rather than a loose story: it carries
a `manifest.yaml`, so an application mounts it the way it mounts any
game.

Roger Firth specified this game in 1999 so that one story could be
implemented across many authoring systems and compared side by side. It
is deliberately tiny — five or six moves to win — because its purpose is
to hold the story constant while the system varies. This implementation
was written from the published specification.

- **`manifest.yaml`** — the game folder's manifest.
- **`locations.py`** — the map: three rooms, the exits between them, and
  the one binding the story needs.
- **`sidebar.py`** — the side panel: a compass of the exits from the
  room named in the story's `current_location` global, built with
  `ink_engine.game_panel.exits_section()`.
- **`cloak_of_darkness.ink`** — the story source.
- **`cloak_of_darkness.inkj`** — the compiled story, which is the file
  `ink-engine` reads. `.inkj` and `.ink.json` are the same format.

**The map is where the demonstration is.** The three rooms are declared
as a location graph rather than wired to each other by hand, so an
application offers movement by reading `exits_from()` — each exit
carrying the position to draw it at, the label to print, and the knot
and prose for arriving. The foyer's refused exit north is declared
`sealed` with `show_when_blocked`, so it appears in the panel and is
never passable. The return exits from the bar and the cloakroom are
generated by `add_missing_return_exits()` rather than declared, and
arrive through the foyer's own `arrival_knot` and `arrival_text`.

The story still offers every move as an ordinary choice too, so the game
plays to the end in an application that shows no panel. An application
that draws the compass hides the story's `GO` choice, which is the one
`take_exit()` takes.

Draw the map:

```bash
python tools/map_to_mermaid.py examples/cloak_of_darkness
```

The rest of the game state is plain Ink: the cloak's position, the
disturbance counter and the score are variables, and whether the bar is
lit is derived from whether the player is carrying the cloak rather than
stored.

Recompile after editing the story:

```bash
inklecate -o examples/cloak_of_darkness/cloak_of_darkness.inkj \
          examples/cloak_of_darkness/cloak_of_darkness.ink
```

`tests/test_examples_cloak_of_darkness.py` plays it to both endings, so
a story edit that breaks a path fails there. The published walkthrough —
south, north, west, inventory, hang the cloak, east, south, read — wins
with the full score of 2.

Recompile after editing `hello.ink`:

```bash
inklecate -o hello.ink.json hello.ink
```

Play it, from the repository root:

```bash
poetry run python examples/play_hello.py
```

`play_hello.py` is that same program as a file, so you can edit it and
run it again:

```python
import json
from pathlib import Path

from ink_engine.engine import InkRuntimeState, load_list_defs, load_story_root

compiled = json.loads(Path("examples/hello.ink.json").read_text(encoding="utf-8"))
state = InkRuntimeState(load_story_root(compiled), load_list_defs(compiled))

state.continue_story()
print(state.last_turn_text)

for index, choice in enumerate(state.current_choices):
    print(index, choice.text)
```

Pick a choice by index and play on with `state.choose(0)`, then
`state.continue_story()` again.
